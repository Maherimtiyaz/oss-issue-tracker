## #2951 — Unparseable tool-call arguments passed as raw string

**Problem**: tool-call `arguments` that can't be parsed (e.g. malformed JSON) are threaded through as a raw string
instead of being handled/validated, so tools receive garbage or the agent crashes downstream.

**Cause area**: `models.py:193` (tool-call construction), `agents.py:1334` (argument passing), `tools.py:1409`
(tool-call result / parsing).

**Approach** (tests-first):
1. `uv sync` in a smolagents clone; find the tool-call parse path (`python/src/smolagents/`).
2. Reproduce with a fake model message whose tool arguments are malformed JSON.
3. Assert an actionable error (or graceful fallback) rather than a raw string reaching the tool.
4. Add regression test alongside the existing tool-call tests; fix at the parse boundary.

## #2924 — Add `--max-steps` CLI option

**Problem**: the smolagents CLI (`cli` scripts) hard-codes the agent max-step count; users want
`--max-steps <n>` on the command line.

**Approach**:
1. Find the CLI argparse/typer entry (usually `src/smolagents/cli.py`) and the `Agent(max_steps=...)` wiring.

3. Add a CLI unit test using `pytest` + `capsys`/fake model.
