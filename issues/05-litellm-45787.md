## Problem

Requests to a **non-Vertex** pass-through target whose URL contains the substring `predict` are incorrectly routed
into `VertexPassthroughLoggingHandler`. That handler assumes `response["predictions"]`, gets `KeyError('predictions')`,
crashes the `asyncio.create_task` running `pass_through_async_success_handler`, and **SpendLogs are never written** —
even though the HTTP response itself is 200 OK.

Root cause (from issue):
- `PassThroughEndpointLogging.is_vertex_route()` uses **substring matching** (`if route in url_route`) against
  `TRACKED_VERTEX_ROUTES` which includes `"predict"`.
- `transform_vertex_response_to_openai()` → `response["predictions"]` at `vertex_embeddings/transformation.py:227` has
  no guard.

Silent data-loss bug (missing SpendLogs / crash in a background task) — a strong write-up: "requests succeed but
billing is silently dropped."

## Approach

1. Clone `BerriAI/litellm`, `uv pip install -e .` (+ dev deps). Litellm is big but self-contained.
2. Read `litellm/proxy/pass_through_endpoints/` (the handler + `is_vertex_route`).
3. Fix the routing check to match the Vertex path correctly (e.g. exact segment / starts-with on the full path, not
   any substring) — keep `predict` matching only when it is genuinely a Vertex route.
4. Add a guard in the Vertex transformation so a missing `predictions` key raises a clear error instead of a raw
   KeyError, and assert SpendLogs are still written for the non-Vertex case.
5. Add a unit test with a fake URL containing `predict` + a 200 fake response; assert `is_vertex_route` False and the
   latency-callback path succeeds.
