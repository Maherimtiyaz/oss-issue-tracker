## #1697 — `llm --no-stream` fails when endpoint omits `usage`

**Problem**: the non-streaming completion path accesses `response.usage` without a None check; endpoints that omit
`usage` in the response (common for OpenAI-compatible providers) trigger `AttributeError` instead of working.

**Cause area**: `llm/openai_models.py` — the completion path near `:1491` and the streaming-vs-non path near `:1608`.

**Approach** (tests-first):
1. In the same `simonw/llm` clone, write a test with a mocked OpenAI response that has `usage=None` → asserts
   `llm -o openai --no-stream` returns content successfully.
2. Guard the `usage` access (`usage.usage if usage else None`) in the non-stream path.
3. Run `uv run pytest -q` + `uv run black .`.

## #1722 — `Collection.embed_multi` zip mismatch

**Problem**: async batch embedding in `Collection.embed_multi` mismatches the number of collected embeddings vs.
requested rows (iterates/returns fewer items than the model was asked for), producing silently wrong data.

**Approach** (tests-first):
1. Write a failing test with a fake embedding model that returns the expected number of embeddings, asserting all
   rows round-trip.
2. Fix the collection/zipping logic in `llm/collections.py` (embed_multi async path).
3. Run `uv run pytest -q`.
